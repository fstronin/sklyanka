# ADR-0004. Два статичных канала уведомлений, индивидуальный звук — во вторую версию

## Статус

Принято. 26 сентября 2026.

## Контекст

`design/SPEC-original.md §5` требует в первой версии один общий звук и два статичных канала
уведомлений: обычный и настойчивый.

Причина не в экономии, а в устройстве платформы. Начиная с Android 8 (а `minSdk` — ровно 26)
настройки канала уведомлений — звук, вибрация, важность — **неизменяемы после создания**.
Приложение может создать канал и задать его параметры один раз; дальше ими распоряжается
только человек через системные настройки.

Обойти это удалением и пересозданием канала нельзя: система помнит удалённые каналы, и
пересоздание канала с тем же `id` восстанавливает **старый** канал со старыми настройками.
Это не ошибка, а защита от приложений, которые «перенастраивали» себе звук в обход
пользователя.

Значит, индивидуальный звук на каждое лекарство потребовал бы одного из двух:

- канала на каждое лекарство с версионированным `id` (новый `id` при каждой смене звука) —
  список каналов в системных настройках разрастается, старые версии остаются мусором,
  и человек видит там «Магний B6 (3)»;
- собственного проигрывателя поверх молчаливого канала — приложение само играет звук при
  срабатывании будильника, обходя механизм уведомлений; это означает работу с
  аудиофокусом, режимом «не беспокоить», громкостью будильника против громкости
  уведомлений и поведением при заблокированном экране.

Оба пути — заметный объём и новый источник ненадёжности в самой чувствительной части
продукта.

## Решение

Два статичных канала, создаваемых один раз при первом запуске:

| Канал | `id` | Важность | Назначение |
|---|---|---|---|
| Обычный | `reminder_default` | `IMPORTANCE_HIGH` | Напоминание о приёме |
| Настойчивый | `reminder_insistent` | `IMPORTANCE_HIGH` | Повторное напоминание, если приём не отмечен |

Звук — один общий на оба канала. Индивидуальный звук на лекарство отложен во вторую версию
вместе с макетом `design/screens/SoundPicker.dc.html` (`PLAN.md §6`).

Строка «Звук» в настройках в первой версии ведёт к настройкам канала или к короткому
выбору — какой из вариантов, не зафиксировано → `ОВ-11`. Правило поведения настойчивого
канала (сколько повторов, с каким интервалом, до какого события) также не зафиксировано →
`ОВ-11`.

## Последствия

- Напоминания работают предсказуемо и одинаково; поведение звука полностью в руках человека
  через системные настройки — там, где он привык его искать.
- Список каналов приложения в системных настройках остаётся коротким и понятным: два
  пункта вместо «канала на лекарство».
- Индивидуальный звук во второй версии потребует миграции: если он будет сделан через
  каналы на лекарство, появятся новые `id`, и настройки, которые человек изменил в двух
  статичных каналах, не перенесутся. Это нужно будет объяснить в интерфейсе.
- Идентификаторы каналов становятся частью совместимости: их нельзя переименовывать между
  версиями, иначе человек получит канал с настройками по умолчанию и, возможно, беззвучное
  напоминание.
- Полноэкранное напоминание (`§4`, `Reminder.dc.html`) требует разрешения на полноэкранные
  уведомления начиная с Android 14 — отдельный пункт онбординга, не связанный с каналами.

## Альтернативы

**Канал на каждое лекарство с версионированным `id`.** Даёт индивидуальный звук штатными
средствами. Отвергнут для первой версии: список каналов разрастается, версии накапливаются,
удалённые каналы нельзя переиспользовать, и миграция настроек при смене звука невозможна
в принципе.

**Молчаливый канал плюс собственный проигрыватель.** Полный контроль над звуком, один
канал. Отвергнут: приложение начинает играть звук само, в приёмнике будильника, на
заблокированном экране, в Doze, конкурируя с системным «не беспокоить» и режимом вибрации.
Каждая из этих ситуаций — потенциальное беззвучное напоминание, то есть отказ продукта.
Цена ошибки несопоставима с пользой от индивидуального звука.

**Один канал вместо двух.** Проще, но лишает возможности сделать повторное напоминание
заметнее обычного, а это единственный механизм «настойчивости», не требующий собственного
проигрывателя.
