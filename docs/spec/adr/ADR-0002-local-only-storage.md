# ADR-0002. Хранение только на устройстве

## Статус

Принято. 26 сентября 2026. Зафиксировано в `CLAUDE.md` как правило, которое не обсуждается.

Частично пересмотрено решениями ПМ-4, ПМ-5, ПМ-17, ПМ-18 и ПМ-19. Итог на 01.10.2026:

- **аналитический контур — во всех сборках с первой публикации** (ПМ-19): базовая сборка
  объявляет `INTERNET` для Huawei Analytics Kit, события уходят только после единого согласия
  при первом запуске и без медицинских данных; механизм — `ADR-0011`.
  *(Ревизия 07.10.2026: ПМ-31 (03.10.2026, заказчик) вывел аналитику и A/B из первой
  публикации — Huawei-контур не подключается, `INTERNET` не объявлен и запрещён гейтом,
  реализация отдана заглушке NoOp, механизм сбора сохранён; рамки ПМ-19 вступают в силу
  с подключением реального провайдера новым решением. См. `ADR-0011`, `ПМ-31`.)*
- **платный контур H1** (биллинг, cloud AI, sync, push) — `ADR-0010` (создаётся в SKL-50);
- данные о лекарствах, приёмах и профилях не покидают устройство ни при каких условиях.

## Контекст

`design/SPEC-original.md §2` задаёт: «Сеть не требуется. Данные только на устройстве,
облака нет». `§8` описывает единственный механизм переезда — файл
`sklyanka-ГГГГ-ММ-ДД.json`, без облака.

Данные приложения — медицинские: названия лекарств, дозировки, расписание приёма, история
приверженности, имена людей, за которыми ведётся присмотр. По ним восстанавливается
диагноз.

Облачная синхронизация потянула бы за собой сервер, учётные записи, согласия на обработку
персональных данных, требования к хранению медицинских данных в юрисдикциях обоих целевых
магазинов, шифрование канала и хранилища, политику удаления и ответственность за утечку.
Всё это — при аудитории, объём которой сам по себе открытый вопрос (`ОВ-5`). *(Ревизия
07.10.2026: ОВ-5 закрыт — продукт для магазина (решение ведущей сессии 29.09.2026,
подтверждено заказчиком 30.09.2026 — `12-open-questions.md`, `customer-questions.md`);
контекст сохранён как исторический.)*

## Решение

> **Пересмотр ПМ-19 (01.10.2026).** Пункты о полном отсутствии сети и аналитики более
> не действуют: с первой публикации во всех сборках работает аналитический контур
> (`INTERNET`, Huawei Analytics Kit, единое согласие при первом запуске, без медицинских
> данных) — см. `ADR-0011`. Медицинские данные по-прежнему не покидают устройство;
> остальная сеть — только в платном контуре (`ADR-0010`).

Все данные хранятся в локальной базе Room на устройстве. Приложение не содержит сетевого
кода, кроме аналитического контура (`ADR-0011`; пересмотрено ПМ-19: объявление `INTERNET`
и аналитика допустимы в его составе). Резервное
копирование Android отключено (`android:allowBackup="false"`) — иначе копия ушла бы в облако
в обход решения.

Единственный способ переместить данные — файл переноса: выгрузка и загрузка в двух режимах,
«добавить к текущим» и «заменить всё» (`§8`).

## Последствия

- Приватность медицинских данных обеспечивается устройством: они физически не покидают его
  без явного действия человека. Пересмотрено ПМ-19: проверка «нулевой трафик и отсутствие
  `INTERNET` в манифесте» заменена на «трафик только аналитического SDK, до согласия — ни
  одного события» (`НФТ-14/15/16`, `ADR-0011`).
- **Резервной копии не существует.** Потеря или поломка телефона означает потерю истории
  приёмов, если человек не выгрузил файл. Приложение обязано говорить об этом прямо на
  экране переноса данных и не создавать впечатления, что «данные где-то сохранены»
  (`НФТ-13`).
- **Перенос данных из вспомогательной функции становится обязательной.** Это не удобство,
  а единственный путь переезда и единственная возможная резервная копия. Соответственно
  растёт цена ошибки в SKL-19: некорректная выгрузка — это потеря данных, а не неудобство.
- Файл переноса содержит медицинские данные в открытом виде и попадает в файловую систему
  устройства и в системное «Поделиться». Нужна оговорка при выгрузке; шифрование файла
  не зафиксировано → `ОВ-18`. *(Ревизия 07.10.2026: ОВ-18 закрыт — файл переноса без
  пароля (решение ведущей сессии 29.09.2026, подтверждено заказчиком 30.09.2026). Правило
  действует и реализовано (SKL-19): файл не шифруется (ПЕР-33), предупреждения при выгрузке
  обязательны (ПЕР-34) — `07-data-transfer.md`.)*
- Синхронизация между устройствами невозможна: два телефона одной семьи не ведут общий
  набор профилей. Для описанного сценария (`§7` — присмотр со своего телефона) это не
  ограничение: профили живут на одном устройстве по замыслу.
- Политика конфиденциальности для магазинов становится короткой и честной: медицинские
  данные не собираются и не передаются. Пересмотрено ПМ-19: политика дополнительно
  раскрывает обезличенную аналитику и единое согласие при первом запуске (`ADR-0011`).
- Наблюдаемость: локальный журнал срабатываний напоминаний (`НФТ-50` … `НФТ-52`) остаётся
  основой; аналитика (`ADR-0011`) добавляет обезличенные агрегаты, но журнал по-прежнему —
  единственный источник данных о срабатываниях конкретного устройства.

## Альтернативы

**Облачная синхронизация (собственный сервер).** Даёт резервную копию, переезд и общий
доступ. Отвергнута: противоречит `§2`, требует инфраструктуры и юридической обвязки для
медицинских данных, несоразмерна аудитории и превращает частный инструмент в сервис
с обязательствами.

**Резервное копирование Android (Auto Backup / Key-Value).** Бесплатно и прозрачно.
Отвергнуто: копия уходит на серверы Google, что прямо противоречит решению, а на
устройствах без GMS механизм и вовсе не работает — то есть ненадёжен именно на целевой
платформе.

**Huawei Cloud / Drive Kit.** Согласуется с HMS и целевым устройством. Отвергнуто: это
всё равно облако с медицинскими данными, только чужое; плюс привязка к учётной записи
Huawei, которой у человека может не быть.

**Экспорт по расписанию в выбранный каталог.** Смягчил бы отсутствие резервной копии.
Не отвергнут по существу, но в объём первой версии не входит (`§10`): потребовал бы
фоновой работы, а её на EMUI мы расходуем на напоминания.
