# Глоссарий

Доменные термины пишутся одинаково в документации, задачах, Gherkin-сценариях и текстах
интерфейса (`CLAUDE.md`). Колонка «Как называется в коде» — английские идентификаторы,
согласованные с `docs/spec/02-data-model.md`.

Идентификаторы, не вытекающие напрямую из полей модели данных (имена классов, каналов,
состояний), — **предложение исполнителя**: спека имён в коде не задаёт. Поля сущностей и
значения перечислений — не предложение, а прямое следствие `design/SPEC-original.md` §3.

| Термин | Определение | Как называется в коде |
|---|---|---|
| **Склянка** | Название приложения. Слово означает одновременно аптечный стеклянный сосуд и морской получасовой промежуток, отбиваемый ударом в судовой колокол; оба значения — предмет приложения: лекарство и время (`design/SPEC-original.md` §1) | `Sklyanka`, имя пакета `ru.stohastika.sklyanka` |
| **Профиль** | Владелец набора лекарств. Не учётная запись: пароля и отдельного входа нет (`design/SPEC-original.md` §3, §7) | `Profile` |
| **Активный профиль** | Единственный профиль, в контексте которого сейчас работает интерфейс. Все экраны показывают приёмы только его (ПР-10) | `activeProfileId`, `ActiveProfileRepository` |
| **Чужой профиль** | Активный профиль, не принадлежащий владельцу приложения (`Profile.is_self = false`). Требует избыточной визуальной индикации: полоса, подкрашенная шапка, надпись «Профиль · Имя», баннер «Это не ваши приёмы», смена акцентного цвета (`design/SPEC-original.md` §7) | `Profile.isSelf == false`, признак `isForeignProfile` |
| **Владелец приложения** | Человек, которому принадлежит телефон. Представлен профилем с `is_self = true`; такой профиль в базе ровно один (ИНВ-1) | `selfProfile`, `Profile.isSelf == true` |
| **Лекарство** | Препарат вместе с его дозой, расписанием и курсом. Одна запись — один препарат одного профиля | `Medication` |
| **Курс** | Период приёма лекарства: от `start_date` до `end_date` включительно. Пустая `end_date` означает бессрочный приём (ПР-6). Отдельной сущности нет — это пара полей внутри лекарства | `Medication.startDate`, `Medication.endDate` |
| **Приём** | Одно событие приёма лекарства: запланированное или состоявшееся. Одна запись на каждый запланированный приём (`design/SPEC-original.md` §3) | `Intake` |
| **Запланированный приём** | Приём лекарства с режимом «по расписанию»: порождается планировщиком заранее из `times[]` и появляется в списке до того, как наступило его время | `ScheduleMode.SCHEDULED`, `Medication.times` |
| **Приём по потребности** | Приём лекарства, которое принимают не по часам, а когда нужно. Запись создаётся в момент нажатия «Принять», `scheduled_at` равен `acted_at` (ПР-4). Может ограничиваться числом приёмов в сутки | `ScheduleMode.PRN`, `Medication.maxPerDay` |
| **Отметка** | Действие человека, переводящее приём из `pending` в `taken` или `skipped`. Идемпотентна по `intake_id` (ПР-2); гонка часов и телефона решается по первому `acted_at` (ПР-3) | `MarkIntakeUseCase`, `Intake.status`, `Intake.actedAt`, `Intake.source` |
| **Пропуск** | Осознанный отказ от приёма — человек нажал «Пропустить». Отличается от приёма, оставшегося без отметки: тот переходит в `missed` автоматически (ПР-1). В отчёте врачу эти два случая не смешиваются | `IntakeStatus.SKIPPED` — пропуск, `IntakeStatus.MISSED` — без отметки |
| **Окно приёма** | Промежуток после назначенного времени, в течение которого отметка ещё принимается. По истечении окна `pending` автоматически становится `missed` (ПР-1). По умолчанию — до конца суток; точная граница — открытый вопрос (`design/SPEC-original.md` §12) | `intakeWindow`, `MissedIntakeSweeper` |
| **Приверженность** | Доля приёмов, отмеченных как принятые, к числу назначенных за период. Считается из записей `Intake`, отдельно не хранится. Основа экрана «История» и отчёта врачу (`design/SPEC-original.md` §4) | `AdherenceRate`, `CalculateAdherenceUseCase` |
| **Остаток** | Сколько единиц лекарства осталось в упаковке. Уменьшается на дозу при каждой отметке «принято» (ПР-5). Вместе с порогом в днях даёт предупреждение о покупке (ПР-13) | `Medication.stockLeft`, `Medication.stockThresholdDays` |
| **Архив** | Мягкое удаление лекарства: курс убран из «Сегодня» и из планирования, но история сохранена (ПР-11). Делится на «курс завершён» и «убрано вручную»; возврат из архива возможен (`design/SPEC-original.md` §4) | `Medication.archivedAt`, `Medication.archiveReason`, `ArchiveReason.COURSE_FINISHED` / `MANUAL` |
| **Зеркалирование напоминаний** | Дублирование напоминаний профиля на устройство владельца приложения — чтобы ухаживающий получал напоминания подопечного на свой телефон. Настраивается на профиле (`design/SPEC-original.md` §3) | `Profile.mirrorReminders` |
| **Шаблон уведомления Wear Engine** | Готовая карточка уведомления на часах на ноль, одну, две или три кнопки. Отправляется через `HiWear.getNotifyClient()`, подписи задаются `setButtonContents()`, нажатие возвращается в колбэк `Action.onResult` на телефоне. В первой версии — две кнопки, «Принято» и «Пропустить» (`design/SPEC-original.md` §6) | `NotificationTemplate`, `WearNotificationSender` |
| **Lite wearable** | Класс часов Huawei без возможности установки полноценного стороннего приложения. HUAWEI Watch GT 6 Pro относится к нему: приложение на самих часах не требуется и не пишется, хватает шаблона уведомления (`design/SPEC-original.md` §6, НЦ-6) | `liteWearable`, признак `WearDevice.isLite` |
| **Точный будильник** | Системный будильник, срабатывающий в заданную минуту, а не когда системе удобно. Ставится через `AlarmManager.setExactAndAllowWhileIdle` на каждый ближайший приём; требует разрешения `SCHEDULE_EXACT_ALARM` или `USE_EXACT_ALARM` (`design/SPEC-original.md` §5, ПЛ-8) | `ExactAlarmScheduler`, `ReminderAlarmReceiver` |
| **Канал уведомлений** | Системная группа уведомлений Android с собственными звуком и важностью. Настройки канала неизменяемы после создания, а пересоздание канала с тем же `id` восстанавливает старые настройки (ПЛ-10). В первой версии два статичных канала: обычный и настойчивый (`design/SPEC-original.md` §5) | `NotificationChannel`, `CHANNEL_REMINDER_DEFAULT`, `CHANNEL_REMINDER_INSISTENT` |
| **Автозапуск EMUI** | Настройка энергосбережения производителя («Настройки → Батарея → Запуск приложений → вручную»), без которой система выгружает приложение и будильники не срабатывают. Не разрешение Android: запросить программно и прочитать его состояние нельзя (ПЛ-18, `docs/spec/01-platform.md` §6) | Не имеет представления в коде; экран настроек открывается интентом производителя |
| **Перенос данных** | Выгрузка и загрузка всего содержимого одним файлом `sklyanka-ГГГГ-ММ-ДД.json`, без облака. Два режима загрузки: «добавить к текущим» и «заменить всё» (`design/SPEC-original.md` §8) | `DataTransferUseCase`, `TransferMode.MERGE` / `REPLACE` |

## Слова, которых в проекте нет

Термины ниже встречаются в предметной области, но в «Склянке» не употребляются — чтобы
не создавать впечатления, будто соответствующая функция есть.

| Слово | Почему не употребляем |
|---|---|
| Пациент | Приложение не медицинское изделие (П-4). Говорим «профиль» |
| Назначение, рецепт | Приложение не хранит назначение врача и не сверяется с ним; человек вводит расписание сам |
| Аккаунт, вход, синхронизация | Учётных записей и сети нет (П-3, НЦ-2). Профиль — не аккаунт |
| Взаимодействие лекарств, противопоказание | Не входит в продукт (НЦ-1); приложение не знает, что означает введённое название |
| Доза как рекомендация | `dose_amount` — то, что ввёл человек, а не то, что советует приложение (П-4) |
