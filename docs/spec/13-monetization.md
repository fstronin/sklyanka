журнале; этот документ актуализируется вместе с решением.

## 1. Принципы (не нарушаются)

1. **Безопасность бесплатна навсегда и офлайн.** Напоминания, отметка/отмена, история,
   перенос данных не запираются пейволлом и не требуют сети.
2. **Не отбирать данное.** Платное — это только новая ценность, никогда не «отключение боли».
3. **Реклама — нет. Трекинг под рекламу — нет.** Аналитика — да: краши + продуктовые
   метрики (установки, удержание, воронки), без медицинских данных, **во всех сборках
   с первой публикации и по единому согласию при первом запуске** (ПМ-17, ПМ-18, ПМ-19).
   **A/B-эксперименты — часть аналитического контура** (Huawei A/B Testing; ПМ-20):
   включаются там же и тогда же, на тех же данных и согласии; до согласия не применяются,
   офлайн — базовый вариант, пути надёжности не затрагиваются.
4. **Мед-рекомендации по лечению — нет.** Проверка совместимости — справочная, на LLM,
   с явным дисклеймером.
5. **Платёж не показывается в лечебном сценарии** (напоминание, отметка, критический остаток).
6. **Никаких таймеров, скидок «сейчас», искусственного дефицита, настойчивых напоминаний
   об оплате.** Платит тот, кто хочет расширений, а не тот, кого вынудили.

## 2. Структура продукта

### 2.1 База — бесплатно навсегда (ядро работает офлайн)

Всё текущее ядро + **поддержка часов** (возвращена из «отложенного» решением ПМ-2;
`ADR-0009` в силе, пересмотр — в этапе 10 «Платная зона», ПМ-9):

- напоминания и онбординг разрешений, отложить, настойчивый сигнал, вибрация
  с узнаваемым паттерном (ПМ-11);
- отметка/отмена приёма, пропуски, остаток с настраиваемым порогом покупки —
  по умолчанию 7 дней (ПМ-13);
- удаление ошибочно заведённого лекарства — мягкое: скрыто везде, история сохраняется,
  будильники снимаются; до первой отметки «принято», позже — «В архив» (ПМ-24);
- период приёма с пресетами окончания — неделя … год, параметризуемый список (ПМ-12);
- список лекарств «что ближе — то выше»: по расписанию — по ближайшему приёму,
  «по потребности» — ниже, по названию (ПМ-15);
- интервал «Отложить на» — настраиваемый: 5, 10, 15, 30, 60 минут, по умолчанию 15 (ПМ-15);
- проверка напоминаний — понятный человеку экран состояния; технические детали — для
  поддержки (ПМ-16);
- история и приверженность, базовый PDF врачу;
- перенос данных файлом;
- профили с зеркалированием (`mirror_reminders`);
- карточка Wear Engine на часах;
- локализация на английский (US), испанский, немецкий, китайский (упрощённый по умолчанию)
  и казахский — язык интерфейса не отбирается подпиской (ПМ-14, база; в первой
  публикации — ПМ-23);
- плавные переходы между экранами (motion) — единый слой движения по
  `08-design-system.md` §9, база, в первой публикации (ПМ-23, SKL-64).

Аналитика работает и в базе — во всех сборках, по единому согласию при первом запуске и без
медицинских данных (ПМ-19); подпиской она не гейтится и функцией уровня не является. Вместе
с ней во всех сборках работает A/B-контур (ПМ-20): до согласия эксперименты не применяются,
офлайн — базовый вариант, эксперименты идут только на интерфейсе, текстах, UX и воронке
подписки.

### 2.2 «Склянка Про» — подписка (первый платный слой)

- **Умный запас** — авторасчёт пополнения по расписанию и остатку, список в аптеку,
  контроль срока годности.
- **Сложные расписания** — через день, по дням недели, курсы с паузами, циклические схемы.
- **Расширенный отчёт врачу** — тренды, сравнение периодов, графики.
- **Голос/AI (on-device)** — голосовое добавление лекарства и отметка голосом.
- **Проверка совместимости (LLM)** — три уровня, роутинг к врачу, «не знаю» допустимо.

Цена: 149 ₽/мес или 990 ₽/год (подтверждена 30.09.2026, ПМ-10; финальная проверка —
на пилоте SKL-03). Ядро остаётся бесплатным и офлайн.

### 2.3 «Склянка Забота» — подписка, отдельный сетевой контур

Мастер добавляет ведомых (QR/код), получает их статистику и уведомления о пропуске.
Требует: аккаунты/связку, синхронизацию, push (HMS Push Kit + RuStore Push), E2E-шифрование,
правила конфликтов «мастер против ведомого».

Цена: мастер платит 199 ₽/мес или 1490–1990 ₽/год, ведомые бесплатны (до N). Подписка
честна — есть серверные расходы.

### 2.4 Донаты + B2B

- Донаты (CloudTips/Boosty/ЮMoney) — ссылка в «О приложении», ничего не разблокирует;
  попутно датчик готовности платить.
- B2B (позже): лицензии для клиник/пансионатов, тиражи с аптечными сетями и ДМС.

## 3. Монетизационные сценарии

1. **Владимир, 64** (хроника, 4 препарата): база — напоминания и история; Про — умный запас
   снимает тревогу «хватит ли таблетки», голос читает дозу вслух.
2. **Мария, 52** (ухаживает за мамой): база — зеркалирование и отметка; Про — умный запас
   и отчёт по маминым лекарствам, **честно без обещания «узнать, что мама сделала»**
   (это только «Забота»).
3. **Ольга, 41** (схема «через день», сезонные курсы): база — ежедневное расписание;
   Про — сложные схемы совпадают с назначением врача.
4. **Сергей, 58** (приём у врача): база — базовый PDF; Про — нарядный отчёт с динамикой.

## 4. AI в продукте

- **On-device** (база/Про): голосовой ассистент и NL-добавление (HMS ML Kit ASR, без GMS —
  русский ASR проверить первым), помощник приверженности (описательный, не советующий),
  сводка отчёта, нормализация названий при переносе.
- **Облако (Про):** проверка совместимости на LLM — no-retention провайдер, opt-in, дисклеймер.
- **Локальный LLM не планируется**: на API 26 / бюджетном EMUI модели такого размера не живут;
  «AI» здесь — ASR/OCR/классификаторы/правила+ML.

## 5. Сетевой контур и приватность

- **Аналитический контур — во всех сборках, включая базовую** (ПМ-19): базовая сборка
  объявляет `INTERNET` для Huawei Analytics Kit; согласие — единое информированное при первом
  запуске; **до согласия не уходит ни одного события**; отключение — в настройках, раздел
  данных/приватности, немедленно прекращает отправку; отказ не гейтит функции (ПМ-8);
  медданные не уходят никогда (ПМ-17 п. 4).
- **A/B-эксперименты — часть того же контура** (ПМ-20): Huawei A/B Testing (AGC; Remote
  Configuration), те же согласие и правила. До согласия варианты не запрашиваются
  и не применяются; отключение аналитики прекращает и A/B. Получение варианта асинхронно
  и не блокирует сценарии, значение кэшируется; нет сети или ошибка сервиса — базовый
  вариант. Таргетинг — только общие сегменты (локаль/регион, версия, класс устройства,
  канал магазина), без медданных.
- **Остальная сеть — только в платном контуре**, по явному согласию, E2E (студия содержимое
  не читает): биллинг, cloud AI, sync, push (ПМ-4, `ADR-0010`).
- Ядро (напоминания, отметка, история) работает без сети всегда; аналитика и A/B ядру
  не нужны и его сценарии не гейтят.
- Названия препаратов уходят во внешний LLM API → согласие перед первой проверкой +
  no-retention провайдер (платный контур).
- 152-ФЗ: данные о здоровье — спецкатегория; согласие и E2E обязательны, закладываем юр. оценку.
  Для аналитики отдельно проверяется хранение в Huawei Cloud (ПМ-18) — в задаче по аналитике
  до первой публикации.

## 6. Аналитика (рамки)

**Контур и согласие.** Аналитика собирается **во всех сборках и со всех пользователей,
включая бесплатную базу, и не гейтится подпиской** (ПМ-19; прежнее «только платный контур»,
ПМ-17 п. 1, отменено). Она входит в **первую публикацию**: SDK, экран согласия и юр. тексты
готовятся до релиза SKL-22. Согласие — **единое информированное при первом запуске**
(онбординг), раскрытие — в политике конфиденциальности (юр. проверка — предусловие первой
публикации, срок ПМ-10 пересмотрен), отключение — в настройках, раздел данных/приватности,
**немедленно прекращает отправку**; **до согласия не отправляется ни одного события**; согласие
не гейтит функции (ПМ-8). Раздельных тумблеров «сбои»/«статистика» нет. При отказе базовые
функции работают как прежде; остальная сеть (биллинг, LLM, sync, push) — по-прежнему только
в платном контуре.

**Объём (ПМ-18, ПМ-19).** Максимально широкий **без медицинских данных**: действия пользователя
(экраны, тапы, шаги сценариев), воронка paywall → подписка, причины оттока, удержание,
A/B-разрезы, продуктовые агрегаты. Цели — «улучшать опыт» и «понимать, как продавать
подписку».

**Класс метрик.** Краши, установки, удержание, воронки; обезличенные события и агрегаты.
**Никогда** — названия, дозы, формы, имена профилей, расписания и времена приёмов, статусы
конкретных приёмов, остатки упаковки, содержимое приёмов, файла переноса, отчёта врачу
и уведомлений, свободный текст форм; рекламные идентификаторы, session replay и скриншоты.
Белый и чёрный список ПМ-17 п. 4 — в силе без изменений. Полный каталог событий и свойств
фиксируется в задаче по аналитике до релиза (SKL-82, номер-предложение; ПМ-17/ПМ-18/ПМ-19).

**A/B-эксперименты (ПМ-20).** Huawei A/B Testing (AppGallery Connect; в связке с Analytics
Kit и Remote Configuration) — часть аналитического контура: **во всех сборках с первой
публикации**, только после единого согласия. До согласия варианты не запрашиваются
и не применяются; отключение аналитики прекращает A/B — интерфейс возвращается к базовому
варианту. **Fail-safe:** нет сети, таймаут или ошибка сервиса — базовый вариант; получение
асинхронно и никогда не блокирует сценарии; значение кэшируется и переживает перезапуск.
**Надёжность неприкосновенна (П-1):** эксперименты не затрагивают планирование
и срабатывание напоминаний, каналы, онбординг разрешений и другие пути, влияющие
на надёжность и сохранность данных; эксперимент в худшем случае показывает базовый вариант,
но не может быть причиной не сработавшего напоминания. **Первый состав — только интерфейс,
тексты, UX и воронка подписки.** **Таргетинг без медданных:** только общие сегменты —
локаль/регион, версия приложения, класс устройства (HMS / без HMS), канал магазина
и стандартные пресеты AGC; запрещены сегменты про лекарства, диагнозы, историю приёмов,
приверженность, профили и остатки. До H1 (SKL-50/SKL-51) экспериментируются базовые экраны
и онбординг; после запуска платной зоны — воронка paywall → подписка. До релиза — отдельная
задача после аналитики: предложение **SKL-83** (номер и артефакты выдаёт ведущая сессия);
проверка доступности A/B Testing в RU и 152-ФЗ — её обязательные шаги.

**Вендор — Huawei Analytics Kit (HMS), выбран заказчиком (ПМ-18).** Нативен для AppGallery
и HMS-аудитории; ограничения приняты осознанно: события собираются **только на устройствах
с HMS Core** — RuStore-аудитория без HMS не измерима (по ней остаются метрики консоли
RuStore); «Расширенный анализ» в RU отдаёт 404; данные — в **Huawei Cloud**, проверка 152-ФЗ
обязательна в задаче по аналитике до первой публикации (при отрицательном результате вендор
пересматривается). Рекомендация продакт-менеджера была AppMetrica (обе аудитории, российская
юрисдикция данных) — заказчик выбрал нативного вендора платформы.

(SKL-00 … SKL-49), идут релизная подготовка SKL-22 (ключ подписи создан, релизная сборка
подписана) и личный пилот надёжности SKL-03 на Huawei Pura 80 Ultra (EMUI 15 / AOSP 12) —
он же гейт первой версии. **H1 — ближайший горизонт** (ПМ-9); H2 и H3 начинаются после
того, как H1 продаётся. Платная зона выходит **обновлением после публикации базовой
версии** (ПМ-10): релиз базы (SKL-22) не задерживается биллингом. **Аналитика — исключение:
она входит в первую публикацию** (ПМ-19): SDK Analytics Kit, экран единого согласия при первом
запуске и юр. тексты готовятся до релиза SKL-22, поэтому юр. проверка — предусловие первой
публикации, а не H1. **Вместе с ней в первую публикацию входят A/B-эксперименты** (ПМ-20):
Huawei A/B Testing в том же контуре, с офлайн-дефолтом и неприкосновенными путями надёжности;
до релиза — отдельная задача после аналитики (предложение SKL-83).
**В первую публикацию входят также локализация и плавные переходы** (ПМ-23): локализация
(SKL-62) на пять языков переносится с этапа 10 в релизную волну — база, не «Про» (ПМ-14);
плавные переходы между экранами (SKL-64, motion) берутся в работу с motion-спеки дизайнера —
база. Обе работы — бесплатная база, уровни и монетизацию не меняют; отдельно заказчик
фиксирует точечные исправления вёрстки (SKL-90).
Базовые доработки по пилоту SKL-03 (ПМ-11…ПМ-13 и вторая волна ПМ-15/ПМ-16: порядок списка
лекарств, пустая недельная сводка, строки «Звук»/«Отложить на», понятная проверка
напоминаний, имя вендора со ссылкой, быстрый доступ) уровни не меняют: вибрация с узнаваемым
паттерном замораживается **до первой публикации** (каналы неизменяемы, ADR-0004), остальное
идёт базовой волной H1 вне платного контура. Отдельная базовая доработка по запросу
заказчика — **мягкое удаление ошибочно заведённого лекарства** (ПМ-24): предложение задачи,
номер и артефакты — за ведущей сессией; первую публикацию не блокирует.

### 7.1 H1 — первые шаги платной зоны (заготовки задач)

Волна **H1-α** — контур и первые продажи; **H1-β** — AI-слой, когда платная зона уже
работает; часы и базовые доработки по пилоту (ПМ-11…ПМ-16) идут параллельно базовым
развитием (ПМ-2).

> **До релиза SKL-22 нужны две отдельные задачи.** Предложение **SKL-82** «Аналитика во всех
> сборках: Analytics Kit, согласие, каталог событий, переработка гейтов сборки» (номер
> и артефакты выдаёт ведущая сессия; ПМ-19) закрывает аналитику в первой публикации
> и переводит её из состава SKL-50 (там остаётся только воронка продаж поверх уже работающей
> аналитики). Предложение **SKL-83** «A/B-эксперименты во всех сборках: Huawei A/B Testing,
> fail-safe, каталог экспериментов, правила таргетинга» (зависит от SKL-82; ПМ-20) добавляет
> A/B-контур; гейты сборки из SKL-82 сразу учитывают A/B Testing/Remote Configuration как
> часть аналитического контура.

**Почему порядок такой.**

1. H1 открывают SKL-50 и SKL-51: без биллинга и гейта продать нельзя, а без них
   премиум-функции остаются локальными улучшениями. Платная часть контура добавляет
   биллинг, LLM, sync и push; аналитика к этому моменту уже работает во всех сборках
   (ПМ-19), а ядро всё так же не зависит от сети.
2. Первыми продаются осязаемые локальные функции — умный запас, сложные расписания,
   расширенный отчёт: они понятны аудитории, не требуют новых согласий и внешних сервисов.
   Это честная первая продажа (ПМ-8).
3. AI отделён в H1-β: у голоса риск русского ASR на HMS ML Kit, у проверки совместимости —
   галлюцинации и 152-ФЗ (ПМ-6, ПМ-7). Их нельзя продавать раньше, чем платная зона просто
   работает; LLM-проверка не выходит в первой волне, чтобы риск AI не смешивался
   с запуском продаж.
4. Часы стартуют параллельно H1 и начинаются с заявки SKL-01: ревью Wear Engine ручное
   (1–2 недели), а функция базовая и бесплатная (ПМ-2) — держать её за платным контуром
   нельзя.
5. H2 «Забота» ждёт H1: сетевой контур с E2E и push без GMS — самая дорогая и рискованная
   часть дорожной карты; начинать её до доказанной готовности платить нельзя.

## 8. Экономика (сценарии, не прогноз)

Про: конверсия 1–3 %, чек 349 ₽ → 50 тыс. установок ≈ 149–446 тыс. ₽/год; 200 тыс. ≈
594 тыс. – 1,78 млн ₽. Забота: 5–10 % платных из Про, чек 1490 ₽/год. Донаты 0,3–1 %.
B2B — отдельно. Вывод: потребитель покрывает расходы, маржу даёт «Забота» и B2B;
бесплатная база — топливо воронки.

## 9. Риски

- Проверка совместимости на LLM: галлюцинации, ложные «критично». Митигация: «не знаю» как
  валидный ответ, роутинг к врачу, дисклеймер, no-retention.
- Репутационный риск «данные уходят» усиливается аналитикой во всех сборках и `INTERNET`
  в базовой (ПМ-19) → честная формулировка вместо обещания «`INTERNET` нет»: аналитика
  без медицинских данных, до согласия — ни одного события, отказ не блокирует, выключение
  в настройках; E2E и единое согласие для остальной сети.
- **Аналитика во всех сборках: согласие и юр. тексты — предусловие первой публикации
  (ПМ-19, ПМ-20).** Неготовность политики/согласия (включая раскрытие A/B-экспериментов)
  и юр. проверки задерживает релиз SKL-22 — отдельные задачи до релиза (предложения
  SKL-82 и SKL-83) с юр. проверкой в составе.
- **Вендор аналитики — Analytics Kit: HMS-only и Huawei Cloud (ПМ-18).** RuStore-аудитория
  без HMS Core в метрики не попадает (митигация: метрики консоли RuStore по этой части,
  фиксация охвата как ограничения); «Расширенный анализ» в RU недоступен (404) —
  митигация: опираться на доступные отчёты, дублировать ключевые метрики агрегатами;
  данные о здоровье — спецкатегория 152-ФЗ, хранение в Huawei Cloud → обязательная
  юр. проверка в задаче по аналитике (SKL-82, номер-предложение), при отрицательном
  результате — пересмотр вендора.
- **A/B Testing: доступность в RU, HMS-only, Huawei Cloud (ПМ-20).** У Analytics Kit в RU
  уже недоступен «Расширенный анализ» (404) — работоспособность A/B Testing проверяется
  в задаче до первой публикации; RuStore-аудитория без HMS не экспериментируется; данные —
  в Huawei Cloud, 152-ФЗ-проверка общая с аналитикой. Митигация: проверка сервиса и юр.
  оценка — обязательные шаги задачи (предложение SKL-83); при недоступности сервиса состав
  A/B в первой публикации решает заказчик, аналитика выходит независимо.
- **A/B-эксперименты и надёжность (П-1).** Эксперимент не должен влиять на срабатывание
  напоминаний. Митигация: эксперименты только на интерфейсе, текстах, UX и воронке подписки;
  запрет на планирование, каналы и онбординг разрешений; асинхронное неблокирующее получение
  варианта; офлайн — базовый вариант (ПМ-20).
- Push без GMS (HMS + RuStore) — самое технически больное место H2.
- Правила магазинов для health-категории → строже ревью, категория «Здоровье и фитнес».

## 10. Не делаем

Реклама, продажа данных, подписка на напоминания, лимит числа лекарств, блокировка экспорта,
таймеры/скидки, «пробный период с автосписанием», плашки во время приёма, LLM-вывод
«нельзя принимать» (только «проконсультируйтесь»).

## 11. Открытые решения

Решено 30.09.2026 (ПМ-10):

1. **Цены** — подтверждены: 149 ₽/мес и 990 ₽/год; окончательная проверка — на пилоте
   SKL-03.
2. **Биллинг H1** — подключаются **оба канала**: RuStore Billing и AppGallery IAP.
3. **Срок выпуска платной зоны** — обновлением после публикации базовой версии (SKL-22).
4. **Юр. часть** — черновики (политика конфиденциальности, оферта, согласие на обработку
   персональных данных по 152-ФЗ) готовит студия, проверяет юрист заказчика; готовность —
   предусловие старта H1.

Решено 01.10.2026 (ПМ-18):

5. **Вендор аналитики** — **Huawei Analytics Kit** (HMS), выбор заказчика; ограничения
   (события только на устройствах с HMS Core, «Расширенный анализ» 404 в RU, Huawei Cloud)
   приняты осознанно; проверка 152-ФЗ — обязательный шаг SKL-50, при отрицательном
   результате вендор пересматривается.
6. **Согласие на аналитику** — **единое информированное** при входе в платный контур,
   раскрытие в политике конфиденциальности, отключение в настройках; раздельных тумблеров
   «сбои»/«статистика» нет (пересмотр п. 3 ПМ-17).
7. **Скрытый сбор и продажа данных о медикаментозных интересах** — отклонены и зафиксированы
   как блокер (152-ФЗ, политики AppGallery/RuStore, ПМ-5/`CLAUDE.md`); не реализуются.

Решено 01.10.2026 (ПМ-19):

8. **Аналитика во всех сборках** — контур расширен на базу и платный контур, без гейта
   по подписке; входит в первую публикацию (SDK, согласие при первом запуске, юр. тексты —
   до релиза SKL-22); гейты сборки перерабатываются (ПМ-19). Пересматривает ПМ-17 п. 1
   и ПМ-18 в части триггера согласия и сроков; новая задача до релиза — SKL-82
   (номер-предложение).

Решено 01.10.2026 (ПМ-20):

9. **A/B-эксперименты** — Huawei A/B Testing (AGC) **во всех сборках с первой публикации**,
   часть аналитического контура (`ADR-0011`): то же согласие, до согласия не применяются,
   отключение аналитики прекращает и A/B; fail-safe (офлайн/ошибка — базовый вариант, кэш,
   неблокирующее получение), таргетинг только по общим сегментам, надёжность (П-1)
   не затрагивается; первый состав — интерфейс, тексты, UX, воронка подписки. До релиза —
   отдельная задача после аналитики: SKL-83 (номер-предложение), зависит от SKL-82.

Остаются открытыми:

1. Транспорт H2: свой сервер vs ретранслятор E2E.
2. Push: приоритет HMS vs RuStore Push; устройства без обоих.
3. §1 и фраза «не является медицинским изделием» — дополнить «проверка совместимости носит
   справочный характер».
4. Юр. проверка 152-ФЗ по Huawei Cloud (в рамках задачи по аналитике — SKL-82,
   номер-предложение, до первой публикации) — результат может потребовать пересмотра
   вендора (ПМ-18).
5. Доступность Huawei A/B Testing в RU (условия AGC) — проверка в задаче A/B (SKL-83,
   номер-предложение, до первой публикации); результат может изменить состав A/B в первой
   публикации, решение — за заказчиком (ПМ-20).
