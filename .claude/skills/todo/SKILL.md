# Как вести TODO.md задачи

`docs/tasks/SKL-NN/TODO.md` — рабочий чек-лист исполнителя, живой документ. Отмечай пункты по ходу
работы, в том же коммите, что и сделанная работа. Задача закрыта, когда список пуст.

## Структура

```
# SKL-NN · TODO

Задача: [task.md](task.md) · Приёмка: [acceptance.feature](acceptance.feature) · Тесты: [TDD.md](TDD.md)

## Подготовка
## Тесты
## Реализация
## Интерфейс
## Проверка на устройстве
## Документация и закрытие
```

Группа `## Интерфейс` — только если задача трогает экраны. Остальные группы обязательны всегда,
даже если в них два пункта.

## Правила пунктов

- Формат `- [ ] <глагол> …`: пункт начинается с глагола в неопределённой форме или повелительном
  наклонении — «прочитать», «написать», «добавить», «прогнать», «обновить».
- Один пункт — одно действие, выполнимое за один подход. «Реализовать отметку приёма» — не пункт,
  это задача.
- Пункт, который нельзя проверить («разобраться с планировщиком», «сделать красиво»),
  переформулируй в проверяемый или разбей на проверяемые.
- Порядок внутри группы — порядок выполнения. Тесты идут перед реализацией, как требует TDD.
- Обнаруженная по ходу работа сверх объёма задачи не делается молча: заводится отдельная задача
  SKL-NN (скилл `skl-task`), а сюда попадает пункт «завести SKL-NN на …».
- Отменённый пункт не удаляется — вычёркивается `~~…~~` с причиной в скобках.

## Обязательные пункты группы «Документация и закрытие»

Эта группа всегда содержит как минимум:

- [ ] прогнать все сценарии `acceptance.feature` — зелёные, `@manual` отмечены в чек-листе устройства;
- [ ] обновить статус задачи в `PLAN.md` и `docs/tasks/README.md`;
- [ ] занести открытые вопросы, всплывшие по ходу, в `docs/spec/12-open-questions.md`;
- [ ] проверить, что строки интерфейса вынесены в `strings.xml` и в коде нет русского текста.
