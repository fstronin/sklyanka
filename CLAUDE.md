# Склянка — соглашения проекта

Мобильное приложение для учёта приёма лекарств. Android, HMS, русский язык интерфейса.
Исходная спецификация заказчика — `design/SPEC-original.md`, макеты — `design/screens/`.

## Где что лежит

`design/` не редактируется. Всё уточнённое и изменённое живёт в `docs/v2/`; история — в `docs/spec/`.
Исключение — агент-дизайнер (`.opencode/agent/designer.md`): он работает с макетами
`design/screens/` и может их редактировать только с явного разрешения (пользователь попросил,
либо ведущая сессия предложила и пользователь одобрил).

**Продуктовые решения проходят через агента продакт-менеджера** (`.opencode/agent/product-manager.md`):
он — точка ответов «что входит в базу/премиум», «меняем ли монетизацию», «стоит ли делать фичу».
С 07.10.2026 решения фиксируются записями Р-N в `docs/v2/02-decisions.md`; нормативные документы
ведутся в `docs/v2/` (монетизация — `03-monetization.md`). Журналы ПМ- и ОВ- заморожены как архив.
Перед принятием продуктового решения — спроси продакт-менеджера, если заказчик не решил лично.

## Стек

Kotlin, Jetpack Compose, Room, Hilt, AlarmManager. Минимум API 26. Часы и Wear Engine не поддерживаются (Р-3).
Обоснование и альтернативы — `docs/adr/0001-stack.md`.

## Язык

- Документация, задачи, Gherkin-сценарии, тексты интерфейса — **русский**.
- Код, идентификаторы, имена тестов, сообщения коммитов — **английский**.
- Доменные термины пишутся одинаково везде, см. `CONTEXT.md` (глоссарий контекста).

## Порядок работы над задачей

1. Прочитать `docs/tasks/SKL-NN/task.md` и `acceptance.feature`.
2. Идти по `TDD.md`: сначала падающий тест, потом код, потом рефакторинг.
3. Отмечать пункты в `TODO.md` по мере выполнения.
4. Задача закрыта, когда все сценарии `acceptance.feature` зелёные и `TODO.md` пуст.
5. Обновить статус задачи в реестре `PLAN.md` §4 (единственное место статуса).

## Правила, которые не обсуждаются

- **Надёжность напоминания важнее всего остального.** Пропущенное напоминание — отказ продукта, а не дефект удобства.
- **Профили не смешиваются.** Интерфейс всегда в контексте ровно одного профиля.
- **Ядро работает без сети.** Прочая сеть (биллинг, синхронизация, cloud AI, push) допустима только в платном контуре («Склянка Про»). В платном контуре сеть — только биллинг магазинов и, после отдельного решения о возврате, ИИ-ввод (Р-16): по явному действию человека, после согласия на обработку специальных категорий ПДн, в полном контуре 152-ФЗ. Клиентской аналитики нет (Р-4). Отчёт разработчику возвращается только с реальной отправкой (SKL-103); лгущих заглушек в сборке не бывает (П-7). Данные о здоровье уходят наружу только по согласию; реклама и продажа данных запрещены.
- **Приложение не медицинское изделие.** Никаких рекомендаций по лечению и подбору доз. Проверка совместимости лекарств в продукт не входит (Р-5); ИИ, когда вернётся, переносит назначенное врачом и не советует.
- Токены визуального языка не хардкодятся по месту — только через дизайн-систему (`core-ui/token/`, норматив — `docs/v2/12-design.md`; палитра — «олива на бумаге», Р-20).
