# Заведомые нарушения правил проекта

Этот каталог **не входит в сборку**: он не является модулем, не компилируется
и не попадает ни в один артефакт. Здесь лежат фрагменты, каждый из которых
нарушает ровно одно правило проекта (`docs/archive/tasks/SKL-02/TDD.md §5.3`).

Зачем: без такого набора невозможно отличить «правило работает и нарушений нет»
от «правило не срабатывает». Молчащее правило хуже отсутствия правила — оно
создаёт видимость контроля (`TDD §5.2`).

Как проверяется:

```
./gradlew verifyStaticAnalysisRules
```

Задача прогоняет detekt по этому каталогу и требует, чтобы **каждое** проектное
правило нашло хотя бы одно нарушение. Если правило промолчало — прогон падает
и называет это правило.

Посмотреть сами находки:

```
./gradlew detektViolationSamples
cat build/reports/detekt/violation-samples.txt
```
