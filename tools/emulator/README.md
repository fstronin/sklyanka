# Прогон на эмуляторе — порядок запуска

Оснастка задачи SKL-27. Адресовано человеку, который сел за машину с эмулятором и хочет
прогон, а не чтение. Дизайн и обоснования — `docs/archive/tasks/SKL-27/TDD.md`.

**Граница, о которой нельзя забыть.** Эмулятор — AOSP, а не EMUI. Он не содержит
фирменного энергосбережения Huawei и настройки автозапуска, поэтому испытания **И-12
и И-13 на нём не воспроизводятся в принципе**, а **матрица НФТ-40 эмулятором
не покрывается ни одной строкой**. **Гейт НАП-3** (не менее 95 % напоминаний вовремя
за 14 суток непрерывно) **остаётся за живым эталонным устройством Huawei** — SKL-03.
Эмулятор проверяет механику и отсеивает дефекты реализации до живого прогона.

## 1. Что поставить на новой машине

| Что | Зачем | Как проверить |
|---|---|---|
| Аппаратное ускорение | без него загрузка образа — десятки минут, объёмные проверки упираются в таймауты | Linux: `ls -l /dev/kvm` и запись в него разрешена (`sudo usermod -aG kvm $USER`); macOS: HVF включён по умолчанию |
| Совпадение архитектур | эмулятор исполняет только того гостя, для которого в его сборке есть qemu: на Apple Silicon образ x86_64 не поднимается **вовсе** | `uname -m`; ABI по машине подставляет сама матрица (`config.sh`, `skl_host_abi`) |
| Android SDK | `adb`, `avdmanager`, `sdkmanager`, `emulator` | `./avd.sh list` не падает с «SDK не найден» |
| Путь к SDK | скрипты берут его из `ANDROID_SDK_ROOT`, `ANDROID_HOME` или `sdk.dir` в `local.properties` | `echo $ANDROID_SDK_ROOT` |
| Пакеты SDK | `platform-tools`, `emulator`, системные образы матрицы | докачиваются `./avd.sh create` сами |
| Место на диске | около 8 ГБ на образ: системный образ 1,5–3 ГБ плюс раздел данных 4 ГБ | `df -h $HOME/.android` |
| Python 3 | разбор журнала и генератор нагрузки | `python3 --version` |

Матрица образов и что проверяет каждый — `config.sh`, функции `skl_image_candidates`
и `skl_image_purpose`. Образы **без Google APIs** (ПЛ-4): образ с Play Services
проверял бы не тот продукт, и на нём нет `adb root`, нужного испытаниям И-4 … И-6.

## 2. Команды

```bash
cd tools/emulator

./run-all.sh                 # полный прогон: вся матрица, все группы проверок, сбор результатов
./run-all.sh --fast          # быстрый прогон: первый образ матрицы, только группа fast
./run-all.sh --api 35 --keep # один образ, не гасить после прогона

./avd.sh create              # создать образы матрицы (идемпотентно)
./avd.sh list                # что создано и что запущено
./start.sh 35                # поднять образ без окна и дождаться готовности
./install.sh 35              # собрать и поставить отладочную сборку (поверх, подпись та же)
./run-tests.sh 35 fast       # группы: fast | data | heavy | migration | all
./seed.sh 35 --mode day      # синтетическая нагрузка И-16 файлом переноса (один шаг руками)
./seed.sh 35 --mode direct   # та же нагрузка прямо в базу приложения, без рук
./notify-watch.sh 35         # независимое подтверждение показа уведомлений (в отдельном терминале)
./trials.sh list             # разбор испытаний И-1 … И-16: что автоматизируется и чем
./trials.sh auto 35          # провести все автоматизируемые испытания подряд
./trials.sh i3 35            # одно испытание
./collect.sh 35              # снять журнал и посчитать числа гейта
./stop.sh --all              # погасить всё

./run-journeys.sh --happy    # только положительные походы человека + эстафета выживания;
                             # кадры и контактный лист — build/emulator/api35/happy-contact-sheet.png
./run-ui.sh                  # экранный прогон одной командой: окно, Compose-проверки, кадры
./run-ui.sh --keep           # то же, но образ остаётся запущенным — окно видно человеку
./run-tests.sh 35 ui         # только группа ui: Compose-проверки на настоящей платформе
./screenshots.sh 35          # собрать кадры экранного прогона с запущенного образа
```

Скрипты идемпотентны: существующий образ не создаётся заново, запущенный не поднимается
вторым, установка идёт поверх. Данные образа при запуске **не стираются** — испытания
И-1 и И-10 живут между перезагрузками; стереть можно явно: `./start.sh 35 --wipe`.

## 2а. Экранный прогон (SKL-96)

`./run-ui.sh [API] [--keep] [--reuse]` — одна команда: образ поднимается **с видимым
окном** (по умолчанию — API 35, `targetSdk`), ставится свежая отладочная сборка, идут
Compose-проверки группы `ui` (настоящий `MainActivity`, настоящий граф приложения),
кадры экранов собираются на хост. `--keep` оставляет образ запущенным, `--reuse`
не стирает данные приложения (по умолчанию `install.sh --fresh` — кадры не должны
увидеть чужих записей).

Пошагово то же самое: `./start.sh 35 --window` → `./install.sh 35` →
`./run-tests.sh 35 ui` → `./screenshots.sh 35`.

- Отчёты группы: `build/emulator/api35/androidTest-results/ui/`, вывод — `tests-ui.log`.
- Кадры: `build/emulator/api35/ui-screens/<состояние>__<проверка>.png` плюс `manifest.txt`
  (опись «путь + байты»). Кадр — **свидетельство для человека, а не эталон**: ни один
  кадр не сверяется с образцом, хешей и порогов нет; кадры лежат в `build/` и в git
  не попадают.
- **Безоконный запуск остаётся поведением по умолчанию.** Окно включает только признак
  `--window`; `run-all.sh` и механические группы работают как раньше, `-no-window`
  остаётся в `config.sh`.
- Язык кадров — язык устройства: приложение следует локали телефона (SKL-62), поэтому
  на образе с `en-US` кадры английские. Это проверка настоящего поведения, а не дефект;
  для русского кадра поставьте локаль образа `ru-RU` перед прогоном.
- **Состояние проверок — управляемое (SKL-97).** Проверки идут на тестовом Hilt-графе:
  база поднимается в памяти, настройки и согласие очищаются перед каждой проверкой,
  часы задаёт проверка (`FixedTimeSource`), состояние сеется доменными сценариями.
  Поэтому результат не зависит от данных образа и от порядка проверок: повторный прогон
  без `--fresh` даёт тот же результат. Тестовое приложение не исполняет стартовые
  подписки продукта (`SklyankaApp`) — состояние готовит сид проверки.
- **Журнал устройства и сводка.** Весь прогон пишется потоком в
  `build/emulator/api<API>/logcat-ui.txt` (переживает падение проверок), а по отчётам AGP
  печатается и кладётся в `build/emulator/api<API>/ui-summary.txt` сводка
  «проверок / падений / пропущено / время». Сводке нужен `python3`; без него прогон
  **не останавливается**: предупреждение, `ui-summary.txt` с причиной, образ гасится,
  код возврата — код проверок (SKL-98).

Граница та же, что у всего прогона на эмуляторе: **AOSP, а не EMUI**. Рендер EMUI, звук
уведомлений и экран блокировки остаются **эталонному Huawei**; матрица **НФТ-40** и гейт
**НАП-3** экранным прогоном не закрываются, кадр окна приложения не показывает системные
панели и оформление прошивки.

## 3. Где смотреть результаты

Всё под `build/emulator/api<API>/`:

| Файл | Что в нём |
|---|---|
| `results.json` | машинно читаемый результат: отклонение по каждому напоминанию, доля вовремя, перерывы, тихие отказы |
| `summary.txt` | человеческая сводка теми же числами плюс граница прогона |
| `androidTest-results/<группа>/` | отчёты AGP по инструментальным проверкам (XML) |
| `tests-<группа>.log` | вывод прогона группы |
| `platform.txt` | версия платформы образа — без неё результат никуда не переносится (НАП-40) |
| `trial-marks.tsv` | отметки испытаний: что и когда делалось с образом |
| `notifications.tsv` | независимые подтверждения показа уведомлений |
| `journal/sklyanka.db` | снятая копия журнала напоминаний |
| `logcat.txt`, `dumpsys-alarm.txt`, `dumpsys-deviceidle.txt` | материал для разбора отказа |
| `logcat-ui.txt` | журнал устройства за экранный прогон (SKL-97), пишется потоком весь прогон |
| `ui-summary.txt` | сводка экранного прогона: проверок / падений / пропущено / время (SKL-97) |

## 4. Синтетическая нагрузка

Два пути, и выбор между ними не про удобство.

**Файлом переноса** — `./seed.sh 35 --mode day` (или `--mode fast`). Скрипт кладёт файл
на образ (`/sdcard/Download/sklyanka-seed.json`), а загрузку делает человек в приложении:
**«Настройки → Перенос данных → Загрузить»**. Продуктовой точки входа для стенда нет,
и заводить её ради прогона — работа SKL-19, а не оснастки.

**Прямо в базу** — `./seed.sh 35 --mode direct`. Нужен там, где первый путь невозможен:
на образе `aosp_atd` системного выбора файлов нет вовсе (`DocumentsUI` в урезанный под
автотесты образ не входит), и кнопке «Выбрать файл» там нечего открыть. Режим пишет курс
в базу приложения и запускает приложение; **будильники ставит сам продукт**, пересобирая
окно, — измеряется настоящий планировщик, а не подделка. Журнал напоминаний режим
не трогает: числа гейта по-прежнему считаются по тому, что записало приложение.

## 5. Типовые отказы

| Симптом | Причина | Что делать |
|---|---|---|
| `SDK не найден` | нет ни переменных среды, ни `sdk.dir` | `export ANDROID_SDK_ROOT=...` |
| `в SDK нет emulator` | пакет не установлен | `./avd.sh create` докачает; вручную — `sdkmanager emulator` |
| `образ не загрузился за 600 с` | нет аппаратного ускорения либо мало памяти | проверить `/dev/kvm`, поднять `SKL_BOOT_TIMEOUT` в `config.sh`, освободить место |
| эмулятор поднялся, `adb devices` пуст | порт занят чужим эмулятором | `./stop.sh --all`, затем `adb kill-server` |
| `connectedFreeDebugAndroidTest` не видит устройства | Gradle взял другой серийный номер | скрипты сами задают `ANDROID_SERIAL`; вручную — `ANDROID_SERIAL=emulator-5560` |
| миграции падают «нет схемы» | ассеты схем не собрались | схемы лежат в `core-data/schemas` и подключены в `core-data/build.gradle.kts`; пересобрать `:core-data:assembleDebugAndroidTest` |
| `базу приложения снять не удалось` | приложение ни разу не запускалось | `./install.sh`, запустить приложение, повторить `./collect.sh` |
| испытание вышло с кодом 3 | сценарий на эмуляторе не воспроизводится (И-12, И-13) | это не отказ прогона: измеряется только на живом Huawei |
| часы не переводятся | образ с Google APIs, `adb root` запрещён | пересоздать образ из матрицы без GMS |
| «Выбрать файл» ничего не открывает | на образе нет `DocumentsUI` (`aosp_atd`) | нагрузка режимом `--mode direct`; приложение при этом не падает, а сообщает об отказе |
| смена пояса не приводит к пересборке | авто-синхронизация вернула пояс обратно | `./start.sh` выключает `auto_time` и `auto_time_zone`; проверить `settings get global auto_time` |
| `run-ui.sh` не поднимает окно | машина без дисплея или окно недоступно | прогон проверок не требует окна: `./start.sh 35` (без `--window`), затем `./run-tests.sh 35 ui` и `./screenshots.sh 35` |
| группа `ui`: ноль проверок | пакет проверок не совпал или `androidTest` не собрался | проверить `SKL_GROUP_UI_PACKAGES` в `config.sh` и `:app:assembleFreeDebugAndroidTest` |
| `screenshots.sh`: «кадров нет» | проверки не запускались или не дошли до снятия кадра | повторить `./run-tests.sh 35 ui`, посмотреть `tests-ui.log`; проверить, что `:app:connectedFreeDebugAndroidTest` исполнился, а не упал на установке |
| `python3 не найден: сводка не собрана` | в `PATH` нет python3 | поставить python3 (нужен и разбору SKL-27); прогон, кадры и код возврата при этом не страдают |
